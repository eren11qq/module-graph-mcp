# ADR 0002: 模板模式取代目录折叠，改动核对进契约面

- 状态：部分失效（2026-08-31 接受；2026-09-01 §7.1 模块视图 UI 被
  **ADR 0003 修正退役**，模块表与 §7.2 改动核对契约面保留）
- 关联：`CONTEXT.md` 词条（模板模式 / 模块视图 / 文件视图 / 编辑范围 / 越界改动 /
  范围标记）；`docs/MODULE-DESIGN.md` §7；`docs/adr/0003-retire-module-view-ui.md`

## 背景

2026-08-31 grilling 轮（Q1–Q17）定案。目录折叠（Ticket-11）按**目录**语义折叠，
与用户要的**功能模块**语义冲突；用户裁定：删除目录折叠，代之以「模块视图 |
文件视图」双视图切换（默认模块视图，文件视图·全部即原海报模式）。另一条线：
AI 改动经常修一处坏一处、越界乱动其他模块——核对不能靠 AI 自觉，必须由系统用
模块表 + watcher 磁盘事实判定。

## 决策

1. 目录折叠退役，工具栏按钮换成 [模块视图 | 文件视图]（**双视图切换已被 ADR 0003
   退役，文件海报为唯一视图**）；模块表（模块名 + 路径
   清单：目录前缀或显式文件）移入 `src/shared` 成为单一事实源（服务端核对器与
   `get_dashboard_info` 共用），表外文件不进模块视图、不设「未分组」球。
2. 新增 `declare_edit_scope` / `report_edits` 工具对：声明范围（modules + files
   双通道）→ 上报改动 → 服务端核对 → 越界清单；watcher recent-changes 交叉
   验证漏报；read-only 模式同样隐藏 + 审计拒绝。
3. 标记复用现有视觉通道：范围 = 紫环，已改 = 整球紫，越界 = 红角标 + 警示条
   （红环/蓝环已被类型错误与 checking 占用）。

## 后果

- **难逆**：删除一个已交付功能 + 两个新工具进入 evals 契约面（注册表 ⇄ 磁盘
  双向对账），回退成本不是改回一个按钮那么简单。
- **意外**：AI 上报的改动文件若不在声明范围，即使改动本身正确也会被系统判红
  ——设计意图：范围纪律优先，误伤由「显式点名例外文件」吸收。
- **权衡：写死表 vs 配置文件**：v1 模块表是 shared 写死路径前缀（同 region 表
  先例，零协议改动）；任意仓库支持留作配置文件升级路径（Q1 讨论）。

## 补充决策：scope epoch + 证据落盘（Ticket 13，2026-09-01）

聚类海报三修会话实拍：`report_edits` 把**上一会话**的未提交变更记录判成本轮
越界/漏报，agent 只能靠 `report_note` 自证归属；且证据链纯内存——重启或容量
驱逐会灭失越界证据，造成**假绿**。

1. **基线时刻（scope epoch）**：每次成功 `declare_edit_scope` 盖
   `declaredAt`；核对只判 `changedAt >= declaredAt` 的 watcher 证据，更早的
   归入响应新字段 `preexisting`（在/不在范围都列，给人看，不算红、不影响
   `ok`）。未声明 → 不设下界（旧行为不回归）。上报侧不受豁免——自己上报的
   越界永远有罪。同秒竞态按 ≥ 归入代内。
2. **证据落盘**：recent-changes 持久化到
   `<root>/.module-graph/recent-changes.json`（与 reviews.json 同卫生：
   gitignore、坏文件即空、启动回灌、原子写），重启不再清空核对证据。
   残余缺口（接受）：单会话内连改 >100 文件时最旧记录仍滑出核对窗口；
   scope 本身仍会话级（重启即清，重启后未重新声明 = 无下界 = 全判，保守）。

**已知权衡**：声明**之后**落盘的人工（非 agent）改动仍会被算进 agent 代——
单 agent 场景下是可接受的保守方向（宁可错判红让人解释，不做无据豁免）。
